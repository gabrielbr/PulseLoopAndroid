# Audit: following the design system, retroactively (v2.11.56)

Date: 2026-11-04 · PR: see below · Auditor: Claude

## Scope

The design-system repo (Gabriel Design System 0.30.0) now requires every app on it to carry three
design skills and use them on every screen and flow, with an audit file per change. PulseLoop had
neither. This audit covers what shipped without it and what this change does about it.

**Retroactive scope (v2.11.50 → v2.11.55):** the My Health header line (`AppHeader`,
`HealthHeadline`); Today without "Show all"; the accuracy caption moved to Settings; the v2.11.52
audit fixes (type scale, success ≠ mint, one 8dp card radius, rail ≥ 600dp, tonal Record, dark
window, predictive Back); food suggestions in Log Meal; detected workouts (Activity card, Today
line, notification). The v2.11.51 audit (`docs/ui-audit-2026-10.md` lineage) was run with
impeccable and graphic-design-fundamentals; less-is-more did not exist then, so it is run here.

**What this change adds:**
- The three skills in `.claude/skills/` with `VENDORED.md` (0.30.0), and the rule in AGENTS.md.
- **D-11 closed in the app:** releases publish `SHA256SUMS.txt`. The updater installs only when
  the download's SHA-256 matches it (no sum, no install), redirects stay on HTTPS, and the package
  and signing key match the installed app. The sheet follows `docs/self-update.md`:
  "Update available · {v}", **Update · {size}**, **Cancel** while downloading (deletes the part;
  outside taps and Back do nothing), honest failures, all text through `tr()` with pt-BR.
- **Type scale everywhere:** 237 off-scale sizes in 33 files (65 under the 12sp floor) moved onto
  12/14/16/20/24/28/32/40. Mapping: 10, 11 → 12; 13 → 14; 15 → 16; 17, 18 → 16; 22 → 20;
  26 → 24; 30 → 28; 36 → 32. `PulseTypeScaleTest` now scans every source, not 14 files.
- **Postpartum LAM rows:** the ✓/✗ glyphs (mint for "holds") are line icons, 22dp, `success` /
  `warning`, with a spoken label.

`drift.py --pulseloop`: **0 differences** before and after (no token changed).

## impeccable (audit, native / Android)

Read by hand from `.claude/skills/impeccable/reference/audit.native.md` and `android.md` (the
launcher was not run; `detect` is web-only).

| # | Dimension | Score | Key finding |
|---|---|---|---|
| 1 | Accessibility | 3 | Floor of 12sp app-wide; LAM icons labelled. Font-scale behaviour at 200% not re-checked on a device |
| 2 | Performance | 4 | Hashing reads the APK once in 64 KB chunks on IO; no UI-thread work |
| 3 | Appearance & theming | 4 | One scale, one radius, colour roles from GTokens; dark only is D-4 |
| 4 | Platform conformance | 3 | Update dialog follows M3 AlertDialog (TextButtons); buttons elsewhere below the system's 52dp (P2-1) |
| 5 | Adaptivity | 3 | Rail and 720dp cap from v2.11.52; larger small text may wrap more in pt-BR on 360dp phones |
| | **Total** | **17/20** | **Good** (v2.11.51 was 13/20) |

Findings:
- **P1 (fixed) — update installed without a checksum.** `update/UpdateChecker.kt`. A tampered or
  wrong asset reached Android's installer, which only checks the signature. Guideline:
  `docs/self-update.md` checks 1–4. Fixed here: `SHA256SUMS.txt` in `release.yml`, `sha256For`,
  `sha256Hex`, `ApkInstaller.matchesInstalledApp`, HTTPS-only redirects.
- **P1 (fixed) — no way out of a long download.** `UpdateDialog`. Fixed: Cancel.
- **P2 (fixed) — text under 12sp in 65 places**, including widgets and the coach.
- **P2-1 (open) — buttons 40dp, not 52dp.** 142 `Button`/`OutlinedButton`/`FilledTonalButton`
  uses keep Material3's height (their touch target is 48dp, so nothing is untappable). Moving all
  of them is a screen-by-screen change; proposed for the design system's divergence register as
  D-13 (Material3 button height in Compose) so the owner decides: 52dp everywhere through one
  `PulseButton`, or accept M3's 40dp with the 48dp target.
- **P3 (open) — "✓" in "Saved ✓" confirmations.** Text, not an icon; kept.
