# Audit: last-reading label, Vitals translations, Restart ring (2.16.1)

Date: 2026-11-11 · PR: see the PR linking this file · Auditor: Claude Code (the four skills applied by hand from their SKILL.md files)

## Scope

- **Vital cards, top-right label.** "Updated 2h ago" becomes "Last reading 14:28" (weekday added for
  earlier this week, date for older). Trigger: a JRING owner read "Updated 2h ago" as a failed sync.
  Their diagnostics showed the sync had worked: the ring's own history held nothing between 14:28
  and 17:28, so the age was correct but read as the app's fault.
- **Translations.** "bpm range", "% avg", "vs earlier" / "vs baseline" / "vs previous" and the new
  label now go through `tr()`, with pt-BR entries.
- **Ring & sync → Ring management → Restart ring.** A non-destructive action for every ring: drop
  the link, connect again, and let the connect sequence re-send the clock, background-logging
  settings and profile, then run a full history pass. It shows "Restarting…" until the ring has
  dropped and come back, then shows a snackbar. After 45 s with no reconnect, the snackbar says so.
  Factory reset is unchanged and still gated on `FACTORY_RESET`: JRING, YCBT and LuckRing have no
  verified vendor reset command, and AGENTS.md forbids guessing one.

## ux-user-flows (§13 flow review checklist)

Flow: Ring & sync → Restart ring → (link drops) → "Restarting…" → (ring back) → snackbar "Ring
restarted. Syncing now." / (45 s, no ring) → snackbar "The ring didn't come back…" → button enabled again.
